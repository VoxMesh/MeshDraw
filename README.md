# MeshDraw

**Открытая платформа проверяемых вычислений по радиоданным MeshCore**

MeshDraw позволяет получить результат из заранее заданных правил и сохранённых радионаблюдений. Расчёт можно независимо повторить по опубликованному пакету и исходному коду верификатора.

[Главная MeshDraw и список конкурсов](https://voxmesh.github.io/MeshDraw/) · [Первый конкурс и его доказательства](https://voxmesh.github.io/MeshDraw/contests/2026-11-22/)

## Состав репозитория

В `docs/` находятся главная страница, публичный список конкурсов `contest-catalog.json` и отдельные страницы с проверочными пакетами в `docs/contests/<public_slug>/`. В `meshdraw_public/` — Python-проверка публичного пакета, в `meshdraw_core/` — ядро v0.2 для отдельного формата локального расчёта. Архивная проверка использует профиль `archive-input-v1` и операции ядра для квантования и отображения на билеты.

Приём заявок, реестр участников и получение исходных наблюдений относятся к закрытому приложению. Этот репозиторий предоставляет страницу конкурса и исходники проверяющего компонента. Регистрация на странице недоступна.

## Локальная проверка

Нужен Python 3.12. Для тестов JavaScript нужен Node.js 22 или новее. Выполняйте команды из корня полученной копии в локальном терминале с правами текущего пользователя.

```text
python -B -E -S -m meshdraw_public tests/fixtures/synthetic/verification.json
python -B -E -S -m unittest discover -s tests -v
node --test tests/public_web_vectors.mjs tests/home.mjs
python -B -E -S tools/build_contest_catalog.py --check
```

Первая команда пересчитывает отдельный учебный пакет и выдаёт `MATCH` с билетом `0002`. Учебный пакет находится в тестовых данных. Для просмотра страницы запустите сервер каталога сайта. Он слушает loopback-порт 8000. Остановка — Ctrl+C.

```text
python -m http.server 8000 --bind 127.0.0.1 --directory docs
```

Откройте [локальную страницу](http://127.0.0.1:8000/). Браузерный пересчёт использует Web Crypto и BigInt. При размещении `docs/` на GitHub Pages относительные ссылки работают под префиксом проекта.

## Состояние конкурса

Страница сверяет ревизию и SHA-256 файлов `RELEASE.json`, `result.json` и `verification.json` с `show-status.json`. В режиме `NO_CONTEST` с `state: null` доступен анонс, а данные о зарегистрированных аккаунтах появятся после публикации официального снимка. До фиксации показываются число зарегистрированных аккаунтов и время снимка. После фиксации публикуются окончательные номера билетов, план и его SHA-256. На странице используется московское время.

Организатор готовит новые ревизии из штатного проверенного экспорта. При отсутствии сохранённого результата `verification.json` содержит `null`. Контрольные суммы файлов и данных каждого конкурса находятся в его `SHA256SUMS.json`.

Полный снимок первого конкурса, включая исходную страницу и её контрольную сумму, находится в `docs/contests/2026-11-22/`. Проверяйте исторический манифест относительно этого каталога. Прежние прямые адреса публичных JSON и файлов проверяющего сохранены в корне сайта. Старые ссылки на разделы результата, правил, билетов и проверки открывают соответствующие разделы архивной страницы.

Для нового конкурса публикация содержит проверенный `catalog-entry.json` с полями `public_slug`, `title`, `prize`, `phase` и `date` в формате `ГГГГ-ММ-ДД`. `public_slug` совпадает с именем папки и имеет формат `YYYY-MM-DD-name`. Он задаётся при создании конкурса и сохраняется при изменении даты итогов. Допустимые фазы — `ANNOUNCED`, `OPEN`, `CLOSED`, `DRAWN`, `CANCELLED`. Скрипт `tools/build_contest_catalog.py` собирает из этих описаний открытый каталог, выводит его в UTF-8 и проверяет совпадение по флагу `--check`. Каталог содержит только перечисленные публичные поля.

## Методика

До чтения архива Comchan публикуются план, его SHA-256 и окончательный список билетов. План задаёт архивный интервал. Профиль `archive-input-v1` отбирает записи приёма пакетов в заданном интервале с измерениями силы сигнала (RSSI) и отношения сигнала к шуму (SNR) от наблюдателей.

Чтобы убрать повторы, профиль оставляет самую раннюю архивную запись для каждой пары «наблюдатель и передача». При совпадении времени выбор определяет идентификатор наблюдения. Записи упорядочиваются по правилам профиля, а RSSI и SNR квантуются до четвертей единицы. Из нормализованных пар формируются байты и вычисляется их SHA-256. Алгоритм переводит хеш в индекс зафиксированного списка, отбрасывая значения вне полного кратного диапазона.

При повторе расчёта браузер или локальный верификатор проверяет контрольные суммы пакета и сравнивает вычисленный результат с опубликованным. Если план предусматривает резерв, проверяется и порядок резервных билетов.

### Границы проверки

`MATCH` означает совпадение расчёта на предоставленных данных. Пакет содержит подготовленную проекцию сохранённых наблюдений с техническими псевдонимами. Происхождение, соответствие исходному архиву и полнота данных независимо не подтверждены. Модель предполагает доверие к организатору и источнику. Совпадение расчёта не устанавливает криптографическую случайность или устойчивость к выбору входа организатором.
